# 功能清单（Roadmap / 验收口径）

> 本文件是**唯一的需求台账**：所有需求先在这里登记（分配 ID），实现后把状态改成「已完成 + 版本号」。
> 优先级：**P0 = 没有它不能发版**；P1 = 首个正式版之前要有；P2 = 有则更好，可延后。
> 与 [RULES.md](../RULES.md) 冲突时以 RULES.md 为准。

图例：`⬜ 未开始` / `🟨 进行中` / `✅ 已完成` / `⏸ 暂缓`

## D. 统一搜索（SEARCH）—— 本项目核心差异点

### D1. 规则

| ID | 功能 | 优先级 | 验收要点 | 状态 |
|---|---|---|---|---|
| SEARCH-01 | 直播板块发起跨库搜索 | P0 | 直播模式按搜索键 → 同时检索「本地频道库」与「影视源」 | ✅ 0.2.9.2：`SearchRepository`（core:data）把「本地频道 + 本地影视快照 + 远端多源」合成一条 `Flow<SearchOutcome>`；频道走 SQL（去空格后 LIKE，只搜启用的源），影视先读 `media` 快照再并发回源；搜索界面随 SEARCH-03 接上 |
| SEARCH-02 | **类型白名单（硬规则）** | P0 | IPTV scope 结果**有且只有**：直播频道、电影、动漫、电视剧、体育、综艺；短剧/纪录片/资讯/预告片/未分类**一律不出现**；过滤在 Repository 层完成；有全类型单测（见 RULES §3.2） | ✅ 0.2.9.2：白名单在 `SearchRepository` 出厂的**每一帧**上生效（`filterForScope`），UI 拿不到非法类型；单测从仓库出口断言「恰好等于六类」「白名单外四类一条都不出现」 |
| SEARCH-03 | 结果分区展示 | P0 | 「直播频道」与「影视」两个分区，焦点默认落在直播频道区第一条 | ✅ 0.2.9.3：一张纵向网格装两段（段头占满一行、带条数），上下键走到底就是全部结果；**初始焦点给输入框而不是第一条**——结果随输入逐帧补入，抢焦点等于每敲一个字都要重新找光标，按 ↓ 即进结果区（第一条在最前） |
| SEARCH-04 | 影视板块搜索不受限 | P0 | VOD scope 返回全部类型 | ✅ 0.2.9.2：`SearchScope.VOD` 下九类全返回、且不查频道表（单测钉住）；板块入口随 SEARCH-03 |
| SEARCH-05 | 渐进式结果 | P1 | 先出本地频道（< 300ms），远端源结果流式补入，不整页转圈 | ✅ 0.2.9.3：仓库逐帧发射、界面按帧整块重画，底部状态行写「正在搜索…（某源还没回来）」；**不转圈、不整页重载**。<300ms 数值待在真机上实测（记在 M3 验收） |
| SEARCH-06 | 输入方式（TV） | P0 | 屏幕九宫格键盘（遥控器可用）；支持首字母/拼音简写匹配频道名 | ⏸ 0.2.9.3：本版先用**输入框 + 系统输入法**（TV 盒子普遍自带拼音候选，方向键可选词）；自绘九宫格 + 汉字→拼音词典不在本版范围内，卡在「需要一份拼音表与候选词表」 |
| SEARCH-07 | 搜索历史 | P1 | 保留最近 10 条，可单条删除 / 清空 | ✅ 0.2.9.3：DataStore 存一行（换行分隔，关键词是单行的所以不用转义）；去重按归一化口径（「CCTV 1」与「cctv1」算同一个词）、新的在前、上限 10；每条是「词 + 删」两个焦点目标（长按在遥控器上不是标准动作，不能当唯一入口），另有「清空搜索历史」 |
| SEARCH-08 | 无结果引导 | P1 | 说明「直播板块只搜这六类」，并提供「去影视板块搜全部类型」的一键跳转 | ✅ 0.2.9.3：空态写清六类是什么、短剧/纪录片/资讯/预告片要去影视板块，并给一个可点的「去影视板块搜全部类型」（切模式并保留关键词继续搜）；影视板块的空态不再提白名单 |
| SEARCH-09 | 并发与超时 | P0 | 多源并发检索，单源超时 8s，慢源不阻塞已出结果 | ✅ 0.2.9.2：多源并发（信号量限 4）、单源 `withTimeoutOrNull(8s)`；慢源/报错只记自己的源名，已出结果不受影响（虚拟时间单测覆盖） |
